# PDFtrans —— 英文 PDF → 左原文 / 右中文 双语对照 PDF

把一个英文论文 PDF（本地文件）逐段翻译，产出**同一页左栏英文原文、右栏中文译文**的对照 PDF。
左栏是原页面的矢量嵌入——排版、公式、图表、字体原样保留，文字仍可选中复制；右栏是对齐后的中文译文。

图表本身也能翻译：图内英文标签、表格单元格会被替换成中文，位置与左栏一致。
翻译引擎在图形界面里选，可以随时增删/更换 API，不用改代码。

---

## 功能总览

| 能力 | 说明 |
|---|---|
| **左原文 / 右译文对照** | 左栏矢量嵌入原页（可选位图），右栏中文；文字可选中、可搜索 |
| **两种排版模式** | `smart`（整宽译文流）与 `region`（**按原文栏结构 2×2 对照**，双栏论文用） |
| **栏结构自动检测** | 逐页识别 单栏 / 双栏 / 混排；带图文分区的页会分段独立判栏 |
| **图表也翻译** | 图内标签与表格单元格替换为中文（矢量文字重排，非截图覆盖） |
| **图表按位插入** | 图片与表格按原文位置插进右栏对应位置，并排的多图保持并排 |
| **续页不丢内容** | 译文放不下时**紧跟被续页**插入续页，续页左栏留空、右栏从页顶续排 |
| **三类内容分流** | 正文 / 页脚注释 / 图表标题分开翻译，图内噪音（坐标轴数字等）直接剔除 |
| **译文缓存** | 按**输入文件**缓存，换输出名也命中；中断重跑不重复计费 |
| **多引擎** | DeepSeek / 硅基流动 / 通义千问 / Kimi / 智谱 / OpenAI / 本地 Ollama / 免 Key 网页引擎 |
| **成本可控** | `--dry-run` 零成本验证排版；`--render-only` 用缓存重新排版不花钱 |

## 快速开始

```bat
:: 1) 首次安装（装依赖到项目内 deps\）
powershell -NoProfile -ExecutionPolicy Bypass -File setup.ps1

:: 2) 配置 API Key（放环境变量，别写进 settings.json）
setx DEEPSEEK_API_KEY sk-your-key-here
::    然后重开一个终端

:: 3) 把论文放进 input\，翻译
cd tool
run.cmd ..\input\你的论文.pdf --pages 1-5 --layout region --translate-figures
```

`--pages 1-5` 先翻 5 页看效果，满意后去掉该参数翻整篇。

## 程序做了哪些处理

### 1. 先把内容分成三类，再分别翻译（smart 排版，默认）

论文里的文本块性质差别很大，混在一起翻译就会出现「右栏全是坐标轴数字」这种可读性灾难。程序按**字号 + 位置 + 形态**先分类：

| 类别 | 判定依据 | 处理方式 |
|---|---|---|
| **正文** | 页面主字号（约 10pt） | 翻译，排成**一条跨页连续的正文流** |
| **页脚注释** | 比正文小 1~2pt、位于页面下部、以 `∗` `†` `1` `2` 等开头 | 单独翻译，排成 `[注]` 区；当页放不下就移到文末附录 |
| **图表标题** | 以 `Figure 1:` / `Table 2:` / `图 3：` 开头（要求有冒号） | 单独翻译，排成 `[图/表]` 区 |
| **表格内容** | 表格标题上方的**纵向横带**（表格宽度常跨整页，所以只按纵向范围圈定） | 翻译后**按行还原**成紧凑表格摘要，跟表格标题排在一起 |
| **图表内文字** | 字号 ≤ 正文 −2.6pt（坐标轴数字、图例、柱状标签） | **直接丢弃，不翻译** |
| **零碎短文本** | ≤60 字、无中文、不成句、非小节标题（如轴标签） | 不送正文流，避免一行一个词的碎片 |
| **页眉页脚 / 页码** | 页边区域短文本、纯数字 | 直接丢弃 |

实测 31 页论文：正文 253 块、注释 5 条、图表标题 34 条、表格单元格 46 个；**剔除图表噪音 336 块 + 页眉页脚 31 块**。图表噪音只占约 4.5% 字符，却曾污染 13+ 页的右栏。

表格摘要长这样（`|` 分隔同一行的单元格，与左栏表格逐行对应，方便核对数字）：

```
表格内容：
治疗组 (%) 对照组 (%) 差异 (%)
编码经验年数
1-3年 2 (0.077) 2 (0.077) 0 | 4-6年 10 (0.385) 9 (0.346) 1 (0.038)
```

### 2. 正文跨页连续，不再被注释割断

右栏固定三段顺序：**正文流 → `[注]` 注释 → `[图/表]` 图表标题与表格**。
正文是一条连续的流：一页排不完就接到下一页右栏顶部，并在页眉标注「正文接上页第 N 页」。所以第 9 页末尾的句子会在第 10 页右栏顶端接着读，中间不会被脚注插断。

装不下时还有兜底：

- 右栏空间不足的注释 / 图表标题 → 收进**文末附录页**（标注对应原文页码），**绝不丢内容**；
- 正文本身很长的页 → 生成**续页**（见下一节）。

### 3. 区域化排版（`--layout region`，2×2 对照）

默认的 smart 模式是「左半页原文 | 右半页一条整宽中文流」。对**双栏论文**这会把译文挤成一条，图片位置也对不上。`--layout region` 换成按原文栏结构排版：

```
┌─────────────┬─────────────┐
│  原文左栏    │  原文右栏    │   ← 原样
├─────────────┼─────────────┤
│  译文左栏    │  译文右栏    │   ← 与原文栏一一对应，逐段对齐 y 位置
└─────────────┴─────────────┘
```

实现要点（`structlab.py` / `regionlayout.py`）：

1. **先检测栏结构**：`page_layout()` 按纵向带切分，逐带声明 单栏 / 双栏 / 整页宽；
   页眉页脚按**位置区间**剔除（奇偶页页眉文本不同，按文本匹配会漏）
2. **图表带参与分区**：一个图表带把页面切成上下段，**每段独立判栏**。
   否则「上面单栏图 + 下面双栏正文」的页会被顶部块带偏，整页误判成单栏
3. **判栏排除整宽块**：整宽图注/小标题横跨两栏，混进来会把左栏的 x 区间算得过宽，
   进而把双栏误判成单栏；栏宽取「簇内宽度的中位数与 0.75 分位的较大者」，
   避免被标题页的短行（作者姓名等）带成 86pt 的窄条
4. **图层优先**：图表区域 + 真实表格带构成「视觉层」，是唯一真相。
   落在层内的文字块交给图表流程（图片里已带中文），**绝不重复排一遍**
5. **译文栏等分**（不照搬原文栏宽）：半页内等分两栏各约 290pt。
   照搬 242pt 会让中文挤爆——每行只放 15 字，行数远超原文块高度
6. **只向后推挤**：每段基准 y = max(本栏游标, 原文 y0)，绝不向前翻页
7. **三级降级**：缩字号（下限 7.6pt）→ 收紧行距（1.42→1.22）→ 才顺延
8. **放置后重叠自检**：与已放内容相交就整体下移到空隙——这一步让「重叠 17 处 + 顺延 41 块」
   变成「**重叠 0 + 顺延 0**」
9. **续页机制**（见下）

### 4. 续页：放不下的译文另起一页，紧跟被续页

一页译文放不下时，**紧跟在该页之后**插入续页（不是堆到文末）：

- 续页**左栏留空**——一眼就能看出这是译文续页，不会被误认成源页
- 右栏**从页顶连续排**（上对齐），页眉标注「译文续页 · 接第 N 页译文（左栏留空）」
- 本页只排本页译文，上一页的残留不会混进本页中部（早期版本会出现这种"冗余文段"）
- 续页仍放不下就再插一页，`仍未放下` 统计必须为 0

实测（2610.06328v1 前 5 页）：`双栏对应 5/5，顺延 0 块，续页 0 页，仍未放下 0 块`。

### 5. 图表本身也翻译（`--translate-figures`，也可在设置界面勾选）

论文里的图（matplotlib 类）图上有大量英文标签。开启后：

1. **判断图表结构与文字位置**：用图注位置圈出图表区域，再取区域里每个文字 span 的坐标与字号；
   相邻多行标签（`Conceptual ` + `Inquiry`）会合并成一条整体翻译
2. **原文字真删除**：用 `redaction` 从文本层移除英文（白矩形盖不住，英文会留在文本层里，
   看起来就是"图上方重复一段原文"）
3. **中文按原位回贴**：超宽自动缩字号、按框高约束
4. **大小与排版与左栏一致**：图保持图区的原始尺寸，同页多图保留**原相对位置**
   （并排的仍并排，一图一条 clip），整组一起缩放，不拆散
5. **表格按行列重建**：识别 `Table N:` 的表格带 → 由 span 横区间**推断列边界** →
   逐格 redaction + 中文回贴，产出与左栏表格**逐格对照**的中文表格
6. **纯图片/截图不翻译**：整块剪裁保留；若翻译流程没产出内容则**回退嵌原图**，绝不留白
7. **图注不重复**：已随图页绘制的整宽图注会从正文流剔除，避免横跨两栏把正文挤下去
8. 启用后**不再输出 `[图/表]` 旁注**——图注与表格内容已经嵌在图/表里了

> 取舍：右栏是半页宽，若某页的图"原始尺寸"在下移过程中超过剩余空间，
> 整组会等比缩小（保证仍与左栏**构图一致**）。要 1:1 不缩，就得让图跨栏铺满整页。

### 6. 进度条：7 个阶段、带计时与 ETA

一篇 30–40 页的论文要跑 1–3 分钟，中途只有零星日志会看起来像卡死。所以 7 个阶段都有进度条：

```
分析页面（正文/注释/图表分流）  已处理 13 页  [0.4s]
翻译块 ████████░░░░░░░░░░░░░░░░  35% 7/45   第 7 批 · 9 条新译文  [4.5s 剩~35.7s]
✔ 翻译块 45 批 · 27.0s
扫描图内文字 ██████████░░░░░░░░░  55% 17/31  原第 17 页  [0.7s 剩~0.5s]
```

读法：`35% 7/45` 是百分比与已完成/总数；`第 7 批 · 9 条新译文` 是当前动作（由各阶段提供）；
`[4.5s 剩~35.7s]` 是**已耗时 + 预计剩余**（按实际速度动态修正）。

| 进度条 | 含义 | 31 页典型耗时 |
|---|---|---|
| 分析页面 | 逐页抽取文字块并按字号/位置分类 | 0.6s |
| 翻译块 | 正文/注释/图注/表格的 API 翻译（按批） | 27s |
| 扫描图内文字 | 找出图表区域里所有待译标签（含 OCR） | 3.4s |
| 翻译图内文字 | 图内标签的 API 翻译 | 8.4s |
| 生成中文图表页 | redaction 删英文 → 中文回贴 | 19s |
| 排版右栏译文 | 逐页生成对照页、插入图表 | 8.7s |

**输出模式自动适配**：真实终端单行动态刷新；重定向到文件/管道时每跨 10% 打一行（日志干净）；
`--no-progress` 只留阶段标题与小结。判断依据是 `sys.stdout.isatty()`。

用 `--no-progress` 关闭，或在代码里 `PG.set_enabled(False)`。`progress.py` 零依赖，
写入失败会静默忽略，绝不会因为进度条本身让翻译崩掉。

### 7. 其他工程细节

- **页眉页脚 / 水印自动剔除**：跨页重复文字、页边短文本、竖排 arXiv 侧边条都不送翻译，省额度也不污染译文
- **连字修复**：PDF 提取时 `fi`/`fl`/`ffi` 常被拆坏（`there by`、`implemented`），程序会还原；
  跨块被切断的片段（`Ben Sh` + `nd`）会合并后再翻译，避免出现孤立碎片行
- **公式与专有名词保留**：提示词要求公式、变量、引用标记 `[1]`、模型名（Transformer 等）保持原样
- **字体子集化**：只嵌入译文实际用到的中文字形，否则 PDF 会平白胖 12 MB
- **缓存按输入文件名派生**：换输出名、换目录都能命中同一份缓存，不会重复计费
- **断点续跑**：译文按段落哈希缓存在 `cache\`，中断后重跑只翻没翻过的部分。
  缓存目录不可写（磁盘满、只读盘、权限限制）时只打印警告，**翻译和出 PDF 照常完成**
- **配置损坏会报警**：`settings.json` 被其它程序按错误编码改写（表现为"Key 莫名丢失"）时会明确报出路径与原因，而不是静默用默认值
- **原子写入**：输出 PDF 先写临时文件再替换；目标被 PDF 阅读器占用时自动另存为带时间戳的新文件，并在日志里告诉你实际路径
- **进度条**：TTY 下单行刷新，重定向到文件时按 10% 里程碑打印，`--no-progress` 可关闭（详见 `进度条用法.md`）

## 已知取舍

- **右栏是「顺序对齐」而非「坐标对齐」**：译文按段落顺序自上而下排，不与左栏逐行等高
- **单栏论文在 region 模式下仍是单栏**：栏结构检测结果是单栏时只建一条整宽译文栏——
  区域模式**不会把单栏论文硬掰成双栏**，它跟随原文结构
- **右栏字号会自适应**：中文比英文长，放不下会逐档自动缩小；装不完会补续页
- **图表内文字默认不翻译**：坐标轴数字、图例、柱状标签按字号识别后丢弃，避免污染正文流；
  需要时用 `--translate-figures`
- **纯图表格页**：如果一页几乎全是截图/图表，右栏可能只有图表标题，留白较多（内容本来就不需要翻译）
- **扫描版 PDF（纯图片）**：没有文字层，抽不到段落，需先 OCR；图表本身可用 Windows OCR 处理
- **免费 Google 引擎**：国内网络基本连不通（已实测超时），仅作兜底选项保留

## 出问题时

| 现象 | 处理 |
|---|---|
| 提示「还没有配置好」 | 双击 `tool\设置翻译引擎.cmd` 选引擎填 Key，或设 `DEEPSEEK_API_KEY` 环境变量，或加 `--api-key` 临时指定 |
| `Python not found` | 安装 Python 3.10+ 并勾选 Add to PATH；或设 `PDFTRANS_PYTHON` 指向解释器 |
| `Missing PDF library` | 在项目根目录跑一次 `setup.ps1` 即可重新装到 `deps\` |
| 测试连接报 401 | Key 不对或没余额，去对应平台控制台确认 |
| 测试连接报 404 | 接口地址或模型名不对；地址填到 `/v1` 为止，别带 `/chat/completions` |
| 翻译中途报错 | 直接重跑同一条命令，已翻部分走缓存，不重复计费 |
| 输出目录里多出一个带时间戳的文件 | 原成品正被 PDF 阅读器打开，程序无法覆盖，自动另存了；关掉阅读器即可 |
| 报「配置警告：无法解析 settings.json」 | 该文件被别的程序按错误编码改写坏了。删掉它，重新在设置界面填一次引擎信息并保存 |
| 右栏字号看着偏小 | 该页中文比英文长得多，程序自动缩了；可对这几页单独用 `--pages` 翻译并加大 `--font-size` |
| 双栏论文右栏挤成一条 | 加 `--layout region` |
| 区域模式下排版仍有错乱 | 用 `--debug` 看栏结构检测结果，或把问题页号反馈（检测逻辑在 `structlab.py`） |
| 想要旧版排版 | 加 `--legacy-layout`，或在设置界面把「排版模式」改成 legacy |
| 想离线自测整条链路 | 起 `tool\mock_openai_server.py`，再用 `--base-url http://127.0.0.1:18123/v1 --api-key test --model mock` |

## 重新开始这个工程时（贴给 AI 的提示词）

> 如果你想让另一个 AI 会话接着开发本工程，把下面这段连同本 README 一起贴给它。

### 目标与硬性要求

做一个**本地双语对照 PDF 工具**：英文论文 PDF → 左栏英文原文、右栏中文译文，
**逐页对齐、按文本流位置插入翻译后的图表与表格**，供读论文时对照理解。

- **左栏 = 原 PDF 页原样呈现**（矢量嵌入，公式/图表/排版不动，文字可选）
- **右栏 = 中文译文**，并且：
  - **逐页对齐**：第 N 张输出对应原第 N 页；左栏原文停在哪一段，右栏中文也停在**同一段**
  - 右栏尽量**填满**：不要提前翻页、不要大片空白
- **按文本流位置**排序，不要按页面绝对坐标：原文里图/表在哪个段落后，译文里就插在**同一个段落后**
- **跨页连续**：一段话被页边界切开时，下一页右栏要能接着读，并标注「正文接上页」
  **页脚注释绝不能插在正文中间**（这是最初的可读性灾难来源）

### 工作方式偏好（务必遵守）

1. **工作区优先**：先在工作区开发、验证；用户确认成品可用后再部署到 `D:\public\PDFtrans\`
2. **不要每一步都回来问**：工作区内自己做主；只有"会影响成品形态的取舍"才问
3. **不要擅自降级质量**：宁可多花时间做对，不要为了跑通而丢掉已实现的能力
4. **密钥绝不落盘到可分享的文件里**：Key 从环境变量读，`settings.json` 不存 Key；
   提交/分享代码前必须全盘扫一遍 `sk-`
5. **报告要诚实**：做不成的、有取舍的、已知缺陷的，明确列出来，不要报喜不报忧
6. **环境要点**：Windows + PowerShell 5.1（**脚本必须纯 ASCII**，中文注释会因 GBK 读取而破坏语法）；
   `.ps1` 里的 `-f` 格式符会吞掉管道参数，`Write-Error` 在 `$ErrorActionPreference="Stop"` 下会自抛

### 曾经出现过、必须避免的缺陷（回归测试清单）

| # | 缺陷 | 正确行为 |
|---|---|---|
| 1 | 右栏只有坐标轴数字等图表噪音 | 图内小字号文字不送正文流 |
| 2 | 页脚注释插在正文中间 | 正文一条流，注释单列 `[注]` 区 |
| 3 | 右栏提前翻页、大片空白 | 排满才续页 |
| 4 | 图在右栏严重变形/被拆成上下堆叠 | 并排图分列、整组等比缩放、保持构图 |
| 5 | 图上方重复一段英文 | 用 `redaction` 真删除，白矩形盖不住 |
| 6 | 表格内容被丢 | 表格带登记为图层并重建中文表格 |
| 7 | 图注同时进左右两栏、把正文挤下去 | 已随图页绘制的整宽图注从正文流剔除 |
| 8 | 双栏论文译文挤成一条 | `--layout region` 按原文栏分栏 |
| 9 | 单栏页被误判成双栏（或反之） | 判栏排除整宽块、图表带参与分区、栏宽取中位数 |
| 10 | 顺延内容堆到文末 / 混进本页中部 | 紧跟被续页插入续页，左栏留空、右栏从页顶续排 |
| 11 | 换输出名导致全部重译、白花钱 | 缓存按**输入文件名**派生 |
| 12 | `settings.json` 被错误编码改写后静默失效 | 解析失败必须明确报警 |

### 验收方法（每次改完都要跑）

### 当前已知遗留（重启后优先处理）

1. **续页利用率偏低**：续页只排到约 y≈200 就另开一页（理想是排满再开）。
   根因在 `render_deferred` 逐块放置时的游标/高度判断
2. **参考文献页仍有零星碎片**：`nd`、`Sack,` 这类 ≤4 字符的英文片段偶尔单独成行
3. **图注编号偶有串位**：一页多图注时（曾出现"图 19"实为 Figure 20）
4. **跨页/合并单元格的表格**列边界靠几何推断，可能切分不准
